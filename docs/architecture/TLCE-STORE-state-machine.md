# TLCE STORE Submission and Release State Machine

## States

- `draft`: editable by its submitting developer; not visible publicly.
- `submitted`: submission package is locked for initial intake checks.
- `under_review`: an assigned independent reviewer is evaluating the exact submitted version.
- `changes_requested`: reviewer has recorded required corrections; the developer may submit a new revision.
- `approved`: a reviewer has approved the exact version and its evidence; this is not yet public.
- `published`: a separate publisher has created the public catalogue release.
- `rejected`: the submission is closed; a new submission is required.
- `suspended`: public availability is disabled pending an incident or policy review.
- `withdrawn`: the listing is intentionally retired and cannot be silently restored.

## Allowed transitions

| From | To | Authorized role |
|---|---|---|
| draft | submitted | submitting developer |
| submitted | under_review | intake reviewer |
| under_review | changes_requested | assigned reviewer |
| under_review | approved | assigned reviewer, not the submitter |
| under_review | rejected | assigned reviewer |
| changes_requested | submitted | submitting developer |
| approved | published | independent publisher |
| published | suspended | security administrator |
| published | withdrawn | publisher or security administrator |
| suspended | under_review | independent reviewer after incident triage |

All other transitions are denied. In particular, developers cannot approve or publish their own submissions, and approval does not automatically publish.

## Required audit event

Every transition must create an append-only event containing:

- submission ID and immutable revision identifier;
- previous and next state;
- actor ID and role;
- UTC timestamp;
- reason and evidence references;
- reviewer/publisher separation check result.

Do not store identity documents, credentials, private keys, or confidential evidence in the public repository or public catalogue.

## Publication invariant

A public catalogue record must be generated by a trusted server-side publisher from a specific approved revision. The client must never be allowed to set `reviewStatus`, `developerApproved`, or `status` as authoritative values.

The current GitHub Pages implementation is static. This state machine is a design contract only; it is not an active account, authorization, moderation, or publishing service.
