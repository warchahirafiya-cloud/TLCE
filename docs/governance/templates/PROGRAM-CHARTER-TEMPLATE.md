## 8. Entry criteria for Operational
> All mandatory criteria must be evidenced before changing status to Operational.

- [ ] Accountable owner formally appointed.
- [ ] Technical sources and deployment target verified.
- [ ] Required CI checks pass on the release candidate/default branch.
- [ ] Security and privacy reviews recorded.
- [ ] Baseline measures recorded, or explicitly justified as not applicable.
- [ ] Incident response process documented and assigned.
- [ ] Operational documentation published.
- [ ] Detailed checklist in Section 9 completed.

## 9. Operational readiness checklist
- [ ] **Governance:** owner, technical lead, and reviewer formally recorded.
- [ ] **Source control:** repository identified; default branch protection and merge policy verified.
- [ ] **CI/CD:** type checks, tests, and production build pass for the exact release candidate.
- [ ] **Security:** dependency review, secret handling, and least-privilege controls evidenced.
- [ ] **Privacy:** data classification, purpose/legal basis where applicable, retention, and deletion documented.
- [ ] **Observability:** logs, critical alerts, and service-health indicators verified where applicable.
- [ ] **Continuity:** backup and recovery controls documented where stateful data exists; applicability recorded otherwise.
- [ ] **Documentation:** operator runbook and user-facing documentation published.
- [ ] **Acceptance:** owner and independent reviewer record the decision and evidence.
