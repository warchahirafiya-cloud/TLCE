# TLCE Circular Digital Economy

## Purpose
An internal TLCE branch for recirculating underused digital assets. It connects individuals, companies, retailers, malls, developers and digital-recycling partners around assets that can be reused rather than abandoned.

## Supported asset classes
- Domains and digital identities (subject to trademark and transfer checks)
- Source code, reusable components and software templates
- Websites, web applications and mobile applications
- APIs, integrations and digital products
- Dormant or incomplete technical projects

Regulated financial instruments, payment accounts, personal data sets and assets whose transfer is restricted are not treated as ordinary marketplace inventory. Any future support requires separate legal, compliance and custody design.

## Lifecycle
1. Discover and submit an asset.
2. Record provenance, owner authority, condition and technical metadata.
3. Run an explainable indicative appraisal with factor scores and confidence.
4. Verify ownership, licenses, security and privacy before any transaction.
5. Match with buyers, licensees, developers, retailers or rehabilitation partners.
6. Create a rehabilitation plan and isolated technical assessment.
7. Obtain human approval for transfer, relaunch or integration.
8. Record the outcome and asset lifecycle history.

## Appraisal model
The initial deterministic score is a transparent decision-support heuristic:
- Demand: 25%
- Reuse potential: 25%
- Technical quality: 20%
- Evidence completeness: 20%
- Asset condition: 10%

The score is not a currency price or guaranteed market value. Monetary pricing requires comparable transactions, independent inspection, market data and a human-reviewed valuation report. Revenue claims must be evidenced; unverified claims are not accepted as facts.

## Trust and safety requirements
- Verify identity and authority to sell/license before transaction.
- Check domain registrant authority, trademarks and transfer locks.
- Scan source code for secrets, malware, vulnerable dependencies and license conflicts.
- Do not import or execute untrusted code in the TLCE runtime.
- Keep customer data and credentials out of listings and appraisal inputs.
- Use escrow/payment providers only after jurisdictional and compliance review.
- Maintain audit trails, dispute handling, takedown and ownership challenge workflows.
- Require explicit parent-platform approval before production integration.

## Current implementation boundary
This branch provides typed domain contracts, an explainable appraisal heuristic, rehabilitation-plan generation, lifecycle documentation and a TLCE module manifest. It does not yet provide a marketplace UI, database, authentication, escrow, payment processing, automated AI appraisal, third-party integrations or production deployment. No external capabilities are requested by this module at this stage.
